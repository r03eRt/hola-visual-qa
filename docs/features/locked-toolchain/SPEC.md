# Feature: locked-toolchain

Roadmap item #1 (Foundation). Tracking issue: #1.

## Goal

Make installs reproducible and give the repo a working lint step, so every
agent starts from an identical, verifiable toolchain.

## Context and linked canonical specs

- `docs/STATUS.md` — "Repository bootstrap" row is `partial` because versions use
  `latest`.
- `docs/roadmap/IMPLEMENTATION_PLAN.md` item 1.
- ADR-001 (local-first): the toolchain must work offline/deterministically.

## Non-goals

- No browser, scenario, consent, ads, AI or reporting behaviour.
- No dependency upgrades beyond what is already resolved in `package-lock.json`.
- No new CI jobs (CI already runs `npm ci`, typecheck and tests).
- No Prettier/formatting tooling.

## Proposed interfaces and files

- `package.json` — replace every `latest` specifier with the exact version
  currently resolved in `package-lock.json`:
  - dependencies: `@anthropic-ai/sdk@0.115.0`, `dotenv@17.4.2`, `zod@4.4.3`
  - devDependencies: `@playwright/test@1.62.1`, `@types/node@26.1.2`,
    `eslint@10.8.0`, `tsx@4.23.1`, `typescript@7.0.2`
  - Use exact pins (no `^`/`~`) for determinism.
- Add lint devDependencies (pinned): `@eslint/js` and `typescript-eslint`
  (the flat-config helper that bundles the TS parser + plugin).
- `eslint.config.js` — new flat config:
  - extends `@eslint/js` recommended + `typescript-eslint` recommended;
  - `files`: `src/`, `tests/`, `scripts/`, `*.config.ts`;
  - `ignores`: `node_modules`, `reports`, `test-results`, `blob-report`,
    `playwright/`, `dist`;
  - keep rules at recommended; do not weaken thresholds to pass.
- `package-lock.json` — regenerated by `npm install` after the edits.
- `docs/STATUS.md` — flip "Repository bootstrap" note (versions pinned, lint
  works); status may move `partial` -> `implemented` once acceptance passes.

## Acceptance criteria

- [ ] No `latest` specifier remains in `package.json`.
- [ ] All pinned versions match `package-lock.json` and `npm ci` succeeds from
      the committed lockfile.
- [ ] `eslint.config.js` exists and `npm run lint` exits 0 on the current code
      (fix real lint errors; do not blanket-disable rules).
- [ ] `npm run typecheck` still exits 0.
- [ ] `docs/STATUS.md` "Repository bootstrap" row updated honestly.

## Test plan

- `npm ci` on a clean checkout -> succeeds, no lockfile churn.
- `npm run lint` -> exit 0.
- `npm run typecheck` -> exit 0.
- `npm run validate` (typecheck + visual) still runs (visual may fail without a
  BASE_URL/baselines — out of scope; only typecheck must pass here).

## Security/privacy impact

None. Tooling-only. No secrets, network targets or artifacts change. Pinning
reduces supply-chain drift (a security positive).

## Baseline impact

None. No screenshots or expected UI change.

## Dependencies and risks

- Risk: `typescript-eslint` may flag existing code (e.g. `no-explicit-any`,
  unused vars). Mitigation: fix the small number of violations; if a rule is
  genuinely inappropriate for this codebase, disable it explicitly in
  `eslint.config.js` with a one-line justification (not inline blanket disables).
- Risk: TS 7 / ESLint 10 are recent majors; verify `typescript-eslint` supports
  them at install time; pin the compatible version it resolves to.
